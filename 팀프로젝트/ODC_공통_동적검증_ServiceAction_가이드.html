ODC 공통 동적 검증(Validation) & 에러코드 Service Action 가이드

목적: 검증 규칙과 에러코드를 관리 화면(Entity)에서 등록·수정하고, 각 앱/화면은 공통 Service Action 한 번 호출만으로 검증하도록 만든다. 최초 1회 "검증 호출 지점"만 배포하면 이후 규칙 추가·수정·비활성화는 배포 없이 반영된다.

2. 앱 구성

구분 이름 비고
공통 App CommonValidation Entity·Service Action·관리 화면 보유. ODC Library에는 Entity를 둘 수 없으므로 App으로 생성
업무 App Order, Member 등 CommonValidation의 Service Action을 Dependency로 추가
Role ValidationAdmin 관리 화면 접근 권한

Service Action은 네트워크 호출 + 별도 트랜잭션으로 실행된다. 저장 1회당 RunValidation 1회만 호출하도록 설계한다.

3. 데이터 모델

3.1 ErrorCode (Entity)

속성 타입 필수 설명 / 예시
Id Long Integer (Auto) ● PK
Code Text(30) ● ORD-1001
Locale Text(10) ● ko-KR, en-US
Message Text(500) ● 주문수량은 {0}개를 초과할 수 없습니다. (입력: {1})
Severity Text(10) ● Error / Warning / Info
HttpStatus Integer REST 응답용. 기본 400
Description Text(500) 관리자용 설명
IsActive Boolean ● 기본 True
UpdatedBy / UpdatedOn Text / DateTime 변경 추적
  • Unique Index: Code + Locale

필수 시스템 코드 (반드시 등록)

Code Message (ko-KR) Severity
SYS-0001 등록되지 않은 오류가 발생했습니다. ({0}) Error
SYS-0002 검증 규칙 설정 오류입니다. (규칙 ID: {0}, 항목: {1}) Error
SYS-0003 사용자 정의 검사 결과가 없습니다. ({0}) Error

3.2 ValidationRule (Entity)

속성 타입 필수 설명 / 예시
Id Long Integer (Auto) ● PK
Context Text(50) ● 검증 시점. ORDER.SAVE (규칙: 앱.동작)
FieldName Text(50) ● Fields의 Key. Quantity
FieldLabel Text(100) 메시지용 표시명. 주문수량
DataType Text(20) → RuleDataType ● Text/Integer/Decimal/Date/DateTime/Boolean
Operator Text(20) → RuleOperator ● 3.3 참고
CompareValue Text(500) 비교값. 100, A,B,C, 1,100, CHECK_STOCK
CompareField Text(50) 다른 필드와 비교 시 그 필드명 (CompareValue보다 우선)
ErrorCode Text(30) ● ORD-1001
MessageParams Text(200) {0},{1}...에 넣을 토큰. 콤마 구분 (6.4 참고)
Sequence Integer ● 실행 순서 (10 단위 권장)
StopOnFail Boolean ● 위반 시 이후 규칙 중단
IsActive Boolean ● 사용 여부
Remark Text(500) 관리자 메모
UpdatedBy / UpdatedOn Text / DateTime 변경 추적
  • Index: Context + IsActive + Sequence

3.3 RuleOperator (Static Entity)

Code 의미 CompareValue 형식 DataType 사용
EQ 같다 값 ●
NE 다르다 값 ●
GT 초과 값 Integer/Decimal/Date/DateTime
GE 이상 값 〃
LT 미만 값 〃
LE 이하 값 〃
BETWEEN 범위 (경계 포함) 최소,최대 〃
EMPTY 비어 있어야 함 - -
NOT_EMPTY 필수 입력 - -
LEN_GT 길이 초과 금지 → 길이 ≤ N 이어야 통과 N -
LEN_LT 최소 길이 → 길이 ≥ N 이어야 통과 N -
IN 목록 중 하나 A,B,C -
NOT_IN 목록에 없어야 함 A,B,C -
CUSTOM 앱 내부 코드 검사 검사명. CHECK_STOCK -

규칙 의미 통일: 모든 규칙은 "이 조건을 만족해야 통과"로 해석한다. 예) Quantity LE 100 → 100 이하면 통과, 초과하면 ErrorCode 발생.

3.4 RuleDataType (Static Entity)

Text, Integer, Decimal, Date, DateTime, Boolean

속성 설명

7. 소비 앱 공통 래퍼

각 업무 App(Order, Member …)에 한 번만 만든다. 화면마다 만들 필요 없음.

7.1 User Exception

  • BusinessException — ExceptionMessage 에 JSONSerialize(ValidationError List) 저장

Service Action 안에서 발생시킨 User Exception은 호출 앱에서 같은 타입으로 잡을 수 없으므로, 엔진은 결과를 반환만 하고 예외는 각 앱에서 발생시킨다.

7.2 RunValidation (Server Action)

새로운 종류의 CUSTOM 검사를 추가할 때만 배포 필요. 기존 검사의 켜기/끄기, 적용 Context, 에러코드, 순서 변경은 관리 화면에서 처리.

9. 관리 화면

화면 기능
ErrorCodeList / ErrorCodeDetail 코드 검색(Code, Locale), 등록/수정/비활성화, Excel import/export
RuleList Context 필터, Sequence 순 정렬, 활성/비활성 토글
RuleDetail Operator 선택 시 CompareValue 입력 형식 안내 문구 표시. ErrorCode는 Dropdown(ErrorCode Entity)
RuleTest ★ Context 선택 + Key=Value 여러 줄 입력 → ValidateByRules 실행 → 결과 표 표시
RuleHistory 변경 이력 조회 / 이전 값 복원

RuleDetail 저장 시 사전 검증 (Server Action)

  • Operator ∈ {GT,GE,LT,LE,BETWEEN} 인데 DataType 이 Text/Boolean → 저장 불가
  • LEN_GT/LEN_LT 인데 CompareValue 가 정수 아님 → 저장 불가
  • BETWEEN 인데 콤마 없음 → 저장 불가
  • ErrorCode 가 ErrorCode Entity 에 없음 → 저장 불가
  • 저장 시 ValidationRuleHistory 에 Before/After JSON 기록

RuleTest 입력 파싱

입력 예)
CustomerId=1
Quantity=150
StartDate=2026-11-01
EndDate=2026-10-01
#CHECK_STOCK=true      ← CUSTOM 결과를 직접 지정해 테스트

10. 운영 규칙 & 주의사항

10.1 Fields 값 포맷 (반드시 통일)

DataType 변환 함수 포맷
Integer IntegerToText 150
Decimal DecimalToText 1234.5 (소수점 .)
Date DateToText 2026-11-24
DateTime DateTimeToText 2026-11-24 13:05:00
Boolean BooleanToText True / False
미입력 - "" (0, NullDate 넣지 말 것)

관리 화면 CompareValue 도 같은 포맷으로 입력. 화면 표시용 포맷(FormatDecimal 등) 사용 금지.

10.2 명명 규칙

  • Context: 앱.동작 → ORDER.SAVE, MEMBER.JOIN, ORDER.CANCEL
  • ErrorCode: 도메인-4자리 → ORD-1001, MBR-0001, 시스템은 SYS-
  • CUSTOM 검사명: CHECK_대문자 → CHECK_STOCK

10.3 배포 vs 관리화면 반영 범위

변경 내용 배포 필요
에러 메시지 문구 수정 ✕ 불필요
기존 Context에 규칙 추가/수정/비활성화 ✕ 불필요
기존 CUSTOM 검사를 다른 Context에 적용 ✕ 불필요
Fields 에 없던 새 필드로 규칙 추가 ○ 필요 (Fields 구성 수정)
새 Context(새 저장 지점) 추가 ○ 필요 (RunValidation 호출 추가)
새 종류의 CUSTOM 검사 ○ 필요 (Check_ Action + Switch 분기)
새 Operator ○ 필요 (CommonValidation 엔진)

10.4 환경(Stage) 데이터

  • ODC 배포 시 Entity 데이터는 이동하지 않는다 (Dev/QA/Prod DB 분리).
  • ErrorCode, ValidationRule 은 Excel export → 대상 환경 import 로 동기화.
  • import 시 Code+Locale, Context+FieldName+Operator+Sequence 기준 Upsert 권장.

10.5 기타

  • Advanced SQL 로 조건식 문자열을 실행(Expand Inline)하지 말 것 — SQL Injection 위험.
  • 규칙 수가 많은 Context 는 Sequence 앞쪽에 필수값(NOT_EMPTY + StopOnFail) 배치 → 불필요한 평가 감소.
  • 운영 중 규칙 오등록 대비: RuleTest 로 확인 후 활성화, History 로 즉시 원복.
  • SYS-0002 / SYS-0003 이 발생하면 규칙 설정 문제이므로 로그(LogMessage) 남기고 관리자 알림 권장.

11. 구현 체크리스트

CommonValidation App

  • ☐ Entity: ErrorCode, ValidationRule, ValidationRuleHistory (+ Index)
  • ☐ Static Entity: RuleOperator, RuleDataType
  • ☐ Structure: FieldValue, ValidationError, ValidationResult, ErrorMessageResult, ErrorCodeItem (Public)
  • ☐ 내부 Action: FindFieldValue, CompareValues, EvaluateRule, BuildMessageParams, SplitText
  • ☐ Service Action: GetErrorMessage, ValidateByRules, GetCustomChecks, GetErrorCodeList
  • ☐ 시스템 코드 SYS-0001~0003 등록
  • ☐ 관리 화면 + ValidationAdmin Role + RuleTest 화면
  • ☐ Excel import/export

각 업무 App

  • ☐ Dependency 추가 (CommonValidation Service Actions, Structures)
  • ☐ User Exception: BusinessException
  • ☐ Server Action: RunValidation, ValidateOrRaise, (필요 시) Check_xxx
  • ☐ Client Function: GetFieldError, JoinErrorMessages
  • ☐ 저장 Server Action 마다: Fields 구성 → RunValidation → IsValid 분기
  • ☐ 화면: Errors Local Variable + 필드별 메시지 Expression

테스트

  • ☐ 각 Operator 별 통과/위반 케이스
  • ☐ 빈 값 + 비교 규칙 → 통과 / NOT_EMPTY → 위반
  • ☐ 잘못된 규칙(타입 불일치) → SYS-0002
  • ☐ CUSTOM 미구현 → SYS-0003
  • ☐ Warning 만 있을 때 저장 성공 + 안내 표시
  • ☐ Locale 누락 시 ko-KR fallback
